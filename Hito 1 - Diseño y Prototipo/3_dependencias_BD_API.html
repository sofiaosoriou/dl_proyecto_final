Diseño de Tablas — Base de Datos PostgreSQL
2 Puntos
🔄 Modelo C2C (Consumer to Consumer): No hay roles de administrador. Cualquier usuario autenticado puede publicar cafés como vendedor y comprar cafés de otros usuarios. La tabla publications registra al vendedor mediante user_id. Un usuario no puede comprar sus propias publicaciones (validación en backend).

🔗 Relaciones entre tablas
users → publications: Un usuario puede publicar muchos cafés como vendedor (1:N). publications.user_id referencia a users.id.
users → orders: Un usuario puede realizar muchos pedidos como comprador (1:N). orders.buyer_id referencia a users.id.
orders → order_items: Un pedido contiene uno o más ítems (1:N). order_items.order_id referencia a orders.id.
publications → order_items: Una publicación puede aparecer en muchos ítems de pedido (1:N). order_items.publication_id referencia a publications.id.
users + publications → favorites: Un usuario puede marcar como favorito muchas publicaciones (N:M). La tabla favorites actúa como tabla intermedia con restricción UNIQUE(user_id, publication_id).
Restricción C2C: El backend valida que orders.buyer_id ≠ publications.user_id en cada ítem del pedido. Un usuario no puede comprar sus propias publicaciones.
Carrito: El carrito se gestiona en el frontend (Context API / useState). Al hacer checkout se envía al backend para crear la orden y sus ítems.

Contrato de Datos — API REST
2 Puntos
🔑 Autenticación
POST /api/users Registrar nuevo usuario
REQUEST — body
{ "nombre": "String", "email": "String", "password": "String", "foto_url": "String | null" }
RESPONSE — 201 Created
{ "message": "Usuario creado", "user": { "id": Number, "nombre": "String", "email": "String" } }
POST /api/login Iniciar sesión y obtener token JWT
REQUEST — body
{ "email": "String", "password": "String" }
RESPONSE — 200 OK
{ "token": "String (JWT)", "user": { "id": Number, "nombre": "String", "email": "String", "foto_url": "String | null" } } // Sin campo "role" — modelo C2C
👤 Usuarios
GET /api/users/:id Obtener perfil de un usuario 🔒 Privado
REQUEST — headers
{ "Authorization": "Bearer <token>" } // params: id (Number)
RESPONSE — 200 OK
{ "id": Number, "nombre": "String", "email": "String", "foto_url": "String | null", "bio": "String | null", "created_at": "Date" }
PUT /api/users/:id Actualizar perfil del usuario autenticado 🔒 Privado
REQUEST — body + headers
{ "nombre": "String", "bio": "String | null", "foto_url": "String | null" } // Authorization: Bearer <token>
RESPONSE — 200 OK
{ "message": "Perfil actualizado", "user": { "id": Number, "nombre": "String", "bio": "String | null", "foto_url": "String | null" } }
